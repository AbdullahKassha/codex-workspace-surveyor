## Implementation boundary: design decision

Selection accepts a single explicit local absolute database path, checking only that path, its exact ancestors for redirection, and the corresponding `-wal`, `-shm`, `-journal` paths. It never lists the source directory. Reject network/device/alternate-stream paths, links, junctions, hard-linked files, incomplete companions, rollback journals and overlap in either direction. No basename/suffix/age heuristic or Codex-home enumeration exists.

Sources remain external to `CanaryScratch`. Its cleanup methods accept no source registration or source-parent argument. Node measures file identity, size, modification/change timestamps and companion membership before and after. Source content enters only retained helper streams; no Node source hashing/reopening or SQLite source open is used by the runner. Regression tests separately read their invented originals to compare before/after bytes.

The helper verifies fresh actual security descriptors: current-user ownership, present non-null protected DACL, exactly one noninherited current-user FullControl allow rule, intended directory inheritance and no extra ACEs. It protects the root/marker before creating protected children or writing acquisition bytes; every copied object is checked independently. No designated source receives ACL changes. The initial empty-container/marker bootstrap window remains outside the protection claim.

After closure checks, scratch preparation and verified recovery persistence, open every selected source with Open/Read/FileShare.Read before reading any source bytes. Protected empty destinations are precreated so their identities can be authenticated in the recovery record. A later sharing failure disposes earlier handles and writes no source content to those destinations. Hash through retained streams, compare metadata/set, copy only through the same streams into two protected areas, verify bounded bytes and hashes, inspect analysis only, verify untouched acquisition/source contents, and recheck protection/set/metadata before release. Confirm disposal and helper exit before cleanup. This is sequential file-set acquisition, not an atomic database/WAL/SHM snapshot.

Canary bounds: three selected files maximum, 16 MiB each, 32 MiB selected content; two copies within seven scratch files, three directories and 64 MiB plus 8 KiB content. Oversize inputs refuse, with no automatic increase or truncation. Earlier synthetic defaults remain unchanged. The 30-second cooperative deadline is not a hard bound on synchronous filesystem/SQLite operations; no helper kill or forced-crash mechanism is added.

## Copied-only inspection and privacy: design decision

Only the analysis database is opened through SQLite, read-only, defensive, with extensions disabled and zero busy timeout. Fixed setup disables trusted schema and enables query-only operation. The two probes are `PRAGMA schema_version` and `SELECT 1 FROM main.sqlite_schema LIMIT 1`; both values are discarded. The authorizer denies application-table reads, catalog-column reads, attach, writes and other pragmas. No source-supplied SQL, schema names, titles, prompts, transcripts, stored paths or application IDs are queried. SQLite may internally parse schema information; the probe does not establish a usable schema, database integrity or application semantics.

The private helper stdin includes the consented paths and run nonce. The recovery record persists only the scratch locator, identities, nonce and fixed member inventory described below; no personal source path is persisted. Its private held-set frame includes hashes for comparison; these are validated in memory and never become normal output or repository evidence. Only allowlisted outcome/stage/fault categories, counts and booleans leave the runner. Raw stdout/stderr, exceptions, stacks, paths, bytes, hashes, SIDs and account names are withheld. Current-user SID use stays in helper memory.

Input and accepted/buffered stdout are limited to 8 KiB; stderr is discarded without buffering. Oversized/malformed/additional frames and any diagnostics refuse. Total bytes transported or drained by subprocess pipes are not claimed bounded. Invocation uses the explicitly selected host, shell disabled, hidden window, NoProfile/NonInteractive/File, with no policy bypass, compilation, new dependency or elevation. EOF triggers helper disposal; uncertain closure withholds cleanup and further runs.

## Remaining P1 lifetime correction: design decision and synthetic observations

The founder separately approved this narrow correction on 2026-10-06. Review identified a lifetime gap in the checkpoint implementation: the recovery helper waited for a release command under its 30-second receive deadline while Node deleted scratch synchronously. Deadline expiry could dispose the exclusive record handle while Node continued deleting. Prior short-duration exclusion tests did not cover that interval. Preserve those measurements, resolved P2 and all residual disclosures above.

The corrected design keeps identity/inventory authentication in Node and performs every destructive recovery scratch step in the helper owning the exclusive record handle. After authenticating the entire remaining set, Node revalidates before each command. Commands identify only fixed members from the authenticated inventory, in file/child/marker/root order, and carry no arbitrary path. The helper checks the remaining protected set, redirection, marker and emptiness conditions, performs one synchronous `File.Delete` or nonrecursive `Directory.Delete`, then sends bounded count/deletion evidence. Missing already-deleted members are acknowledged without deletion. Node validates each acknowledgment and absence before authorizing another step. The helper never schedules asynchronous deletion and cannot enter disposal until the current synchronous step returns.

The unchanged receive deadline applies between steps and is checked again immediately before deletion. EOF, malformed input, cancellation and an expired deadline prevent the next dispatch. An already executing step finishes under exclusion before stopping. Node's unchanged 30-second timeout can cancel the protocol but cannot release the helper's handle during synchronous work. Missing acknowledgments, uncertain disposal or uncertain helper exit remain unsuccessful residual outcomes; available authentication is preserved. Recovery has no Node scratch-deletion fallback. Existing control-metadata retirement follows only positive scratch absence and confirmed helper closure; it is not claimed atomic.

Eight additional regressions exercise helper-only scratch mutation, strict sanitized acknowledgments, real deadline crossing, EOF/malformed commands before and during dispatch, and late Node authorization. The first attempt must stop with remaining copies/authentication intact and confirmed helper exit; a fresh recovery then completes exact cleanup. A separate 31-second delay between acknowledged steps verifies that late authorization cannot dispatch another deletion. Short in-flight probes cover EOF and malformed commands while exclusion is held. Tests verify intended stages, no later scratch deletion, source/sentinel survival and subsequent successful recovery. The slow probe is deterministic fault injection around a synchronous step, not an empirical simulation of a stalled filesystem call.
